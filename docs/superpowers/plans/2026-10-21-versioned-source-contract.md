# Versioned EN Source Contract Implementation Plan

> **For agentic workers:** Use the executing-plans workflow. Keep the implementation on the existing `feat/en-architecture` branches and implement each task test-first.

**Goal:** Add versioned `.en` contracts, explicit `#?` problem requests, safe migrations, and one CLI-authored run plan consumed by VS Code, while preserving legacy generation behavior.

**Architecture:** EN-Library parses a source file once into a `SourceContract` with structured diagnostics and source positions. Its CLI exposes JSON check/generate/migrate commands; the VS Code extension saves the document and follows the returned plan without parsing `.en` text. Legacy, `en 0.1`, and `en 0.2` behavior stay explicit.

**Tech Stack:** Python 3.10+ standard library, `unittest`, Node.js built-in test runner, JSON Schema, VS Code Extension API.

**Spec:** `docs/superpowers/specs/2026-10-21-en-source-contract.md`.

## Global Constraints

- No model, network runtime, or third-party Python runtime dependency.
- Headerless and `en 0.1` sources keep legacy interpretation; warnings do not alter generated bytes or successful exit codes.
- `en 0.2` uses `#?` problem markers; ordinary comments remain documentation.
- Any source error prevents generation and preserves existing output bytes.
- The extension saves before generation, calls `generate --json`, and executes only the returned run plan.
- Generated artifacts are deterministic and carry a provenance block; migration safety compares generated code bodies excluding that block.

## Review Focus

- A later or duplicate version line inside comments, requests, or string literals is ignored; misplaced standalone headers are diagnosed.
- Indented and tab-indented `#?` requests map recognizer columns back to original source columns.
- Blank `#?` lines inside nonempty requests survive; wholly empty requests fail.
- Legacy `#?` text remains legacy text and migrates without semantic changes.
- Duplicate targets, alias conflicts, and `en 0.2` alias rejection receive deterministic diagnostics.
- CLI JSON and extension use identical runtime, output path, example count, and run arguments; failed generation never runs stale output.

**Decisions:**
- EN-E303 applies when the entire request block has no non-whitespace text; empty `#?` lines inside a nonempty block are preserved.
- `en 0.1` keeps current target case-folding; `en 0.2` accepts lowercase `target python|javascript` only. Pin exact behavior in fixtures.
- Run plan includes exact `run_args`; the extension does not synthesize `--check-examples` from source content.

## Acceptance Criteria

- Headerless, `en 0.1`, and `en 0.2` files follow their documented rules and diagnostics.
- The CLI is the sole source of the extension's interpretation and execution plan.
- Migration is dry-run by default, idempotent, atomic, and guarded by code-body equivalence.
- All generation errors preserve prior outputs and the extension never runs stale generated files.
- Python/CLI/extension results agree on version, target, form, examples, plan, and diagnostics for the fixture corpus.
